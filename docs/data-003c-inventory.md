# ECOM-DATA-003B — Seller & Catalog Domain Model

## 1. Scope

DATA-003B thiết kế Seller Domain và Catalog Domain với 8 bảng:

```text
SELLER MODULE
├── seller_accounts
├── shops
└── shop_memberships

CATALOG MODULE
├── categories
├── brands
├── products
├── product_variants
└── skus
```

Mục tiêu:

- Multi-vendor.
- Một Seller có thể quản lý nhiều Shop.
- Một Shop có nhiều Seller/Member.
- Shop-scoped authorization.
- Product moderation.
- Category hierarchy.
- Product → Variant → SKU.
- Price thuộc SKU.
- Inventory không nằm trong Catalog.
- Product/SKU sử dụng archive thay vì destructive delete.
- Hỗ trợ shipping metadata.
- Media lưu bằng object-storage key.
- Schema sẵn sàng kết nối Inventory, Cart và Order.

# 2. Global Database Conventions

## 2.1 ID

Sử dụng:

```text
PostgreSQL: UUID
Generation: UUIDv7
Generated by: Go application
```

Không sử dụng:

```text
BIGSERIAL
UUIDv4 DB default
```

UUIDv7 phù hợp vì:

- không phụ thuộc PostgreSQL sequence;
- thuận lợi nếu module được tách service;
- khó đoán hơn sequential ID;
- index locality tốt hơn UUIDv4.

---

## 2.2 Timestamp

Mọi absolute timestamp sử dụng:

```sql
TIMESTAMPTZ
```

Convention:

```text
created_at
updated_at
published_at
archived_at
suspended_at
closed_at
invited_at
accepted_at
revoked_at
```

Thông thường:

```sql
created_at TIMESTAMPTZ NOT NULL DEFAULT now()
updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
```

`updated_at` được cập nhật explicit trong SQL UPDATE.

Không sử dụng trigger tự động trong V1.

---

## 2.3 Status

Lifecycle state sử dụng:

```text
VARCHAR + CHECK
```

thay vì PostgreSQL ENUM.

Lý do:

- lifecycle có khả năng thay đổi;
- migration dễ hơn;
- giảm coupling giữa application state machine và PostgreSQL ENUM.

---

## 2.4 Application Validation vs Database Constraints

Application chịu trách nhiệm semantic validation:

```text
email format
phone format
slug generation
input normalization
request validation
business state transitions
```

Database chịu trách nhiệm data invariants:

```text
PK
FK
UNIQUE
tenant ownership
non-negative quantities/prices
allowed status values
timestamp consistency
archive invariants
```

Nguyên tắc:

```text
Application validates semantics.

Database protects invariants.
```

Không duplicate full phone/email regex ở PostgreSQL.

---

# 3. Media Storage Convention

Database không phụ thuộc permanent public URL.

Thay vì:

```text
logo_url
image_url
banner_url
```

sử dụng:

```text
logo_object_key
image_object_key
banner_object_key
```

Ví dụ:

```text
shops/{shop_id}/logo.webp
shops/{shop_id}/banner.webp

products/{product_id}/main.webp

variants/{variant_id}/image.webp
```

Application/CDN resolve object key thành URL.

Nhờ vậy database không bị coupling với:

```text
MinIO
Amazon S3
CloudFront
CDN domain
signed URL
bucket structure
```

# 4. Multi-Vendor Ownership Model

Quan hệ:

```text
User
 │
 ▼
SellerAccount
 │
 │ *
 ▼
ShopMembership
 │
 │ *
 ▼
Shop
```

Một SellerAccount có thể tham gia nhiều Shop.

Một Shop có thể có nhiều SellerAccount.

Do đó:

```text
SellerAccount * ─── * Shop
```

được model bằng:

```text
shop_memberships
```

Không sử dụng:

```text
shops.seller_account_id
```

làm source of truth cho ownership.

# 5. TABLE: `seller_accounts`

**Owner:** Seller Module

## Purpose

Đại diện cho business identity của một User khi hoạt động với vai trò Seller.

```text
users
    → identity/profile

seller_accounts
    → seller lifecycle/capability
```

Một User có tối đa một SellerAccount trong V1.

## Columns

| Column         | Type        | Null | Default     | Constraint |
| -------------- | ----------- | ---: | ----------- | ---------- |
| `id`           | UUID        |   NO | —           | PK         |
| `user_id`      | UUID        |   NO | —           | UNIQUE, FK |
| `status`       | VARCHAR(30) |   NO | `'pending'` | CHECK      |
| `created_at`   | TIMESTAMPTZ |   NO | `now()`     |            |
| `updated_at`   | TIMESTAMPTZ |   NO | `now()`     | CHECK      |
| `suspended_at` | TIMESTAMPTZ |  YES | NULL        | CHECK      |
| `closed_at`    | TIMESTAMPTZ |  YES | NULL        | CHECK      |

## Foreign Key

```sql
FOREIGN KEY (user_id)
REFERENCES users(id)
ON DELETE RESTRICT
```

## Unique

```sql
UNIQUE (user_id)
```

Invariant:

```text
User 1 ─── 0..1 SellerAccount
```

## Status

```sql
CHECK (
    status IN (
        'pending',
        'active',
        'suspended',
        'closed'
    )
)
```

## State Constraints

```sql
CHECK (updated_at >= created_at)
```

```sql
CHECK (
    (status = 'suspended' AND suspended_at IS NOT NULL)
    OR
    (status <> 'suspended' AND suspended_at IS NULL)
)
```

```sql
CHECK (
    (status = 'closed' AND closed_at IS NOT NULL)
    OR
    (status <> 'closed' AND closed_at IS NULL)
)
```

## Indexes

`UNIQUE(user_id)` đã cung cấp index cho User → Seller lookup.

Status index chỉ nên thêm khi query workload thực tế cần:

```sql
CREATE INDEX idx_seller_accounts_status
ON seller_accounts(status);
```

## Delete Policy

Không physical delete SellerAccount sau khi đã tham gia business operation.

Closure:

```text
status = closed
closed_at = now()
```

## Reasoning

Không sử dụng:

```text
users.is_seller
```

vì Seller là một domain entity có lifecycle riêng và tương lai có thể chứa:

```text
KYC
business verification
risk status
payout configuration
seller policies
```

# 6. TABLE: `shops`

**Owner:** Seller Module

## Purpose

Đại diện storefront và tenant boundary chính của Seller/Catalog.

## Columns

| Column              | Type         | Null | Default   | Constraint      |
| ------------------- | ------------ | ---: | --------- | --------------- |
| `id`                | UUID         |   NO | —         | PK              |
| `name`              | VARCHAR(160) |   NO | —         | CHECK           |
| `slug`              | VARCHAR(160) |   NO | —         | UNIQUE          |
| `description`       | TEXT         |  YES | NULL      |                 |
| `logo_object_key`   | VARCHAR(512) |  YES | NULL      |                 |
| `banner_object_key` | VARCHAR(512) |  YES | NULL      |                 |
| `phone`             | VARCHAR(32)  |  YES | NULL      |                 |
| `email`             | VARCHAR(254) |  YES | NULL      | CHECK canonical |
| `is_official`       | BOOLEAN      |   NO | `false`   |                 |
| `currency_code`     | CHAR(3)      |   NO | `'VND'`   | CHECK           |
| `status`            | VARCHAR(20)  |   NO | `'draft'` | CHECK           |
| `created_at`        | TIMESTAMPTZ  |   NO | `now()`   |                 |
| `updated_at`        | TIMESTAMPTZ  |   NO | `now()`   | CHECK           |
| `closed_at`         | TIMESTAMPTZ  |  YES | NULL      | CHECK           |

## Unique Constraints

```sql
UNIQUE (slug)
```

Ngoài ra:

```sql
UNIQUE (id, currency_code)
```

được sử dụng để SKU có thể enforce:

```text
SKU.currency_code = Shop.currency_code
```

bằng composite foreign key.

## CHECK Constraints

```sql
CHECK (
    char_length(btrim(name)) BETWEEN 1 AND 160
)
```

```sql
CHECK (
    slug = lower(btrim(slug))
    AND slug <> ''
)
```

Email chỉ enforce canonical representation:

```sql
CHECK (
    email IS NULL
    OR email = lower(btrim(email))
)
```

Không dùng DB regex cho email.

Application chịu trách nhiệm:

```text
trim
normalize
validate format
```

Phone cũng được validate/normalize tại Go application layer.

Database chỉ giới hạn storage:

```text
VARCHAR(32)
```

Currency:

```sql
CHECK (
    currency_code = upper(currency_code)
    AND char_length(currency_code) = 3
)
```

Status:

```sql
CHECK (
    status IN (
        'draft',
        'active',
        'suspended',
        'closed'
    )
)
```

Timestamp:

```sql
CHECK (updated_at >= created_at)
```

```sql
CHECK (
    (status = 'closed' AND closed_at IS NOT NULL)
    OR
    (status <> 'closed' AND closed_at IS NULL)
)
```

## `is_official`

Đây là platform-controlled field.

Seller không được tự:

```text
is_official = true
```

Chỉ Admin/Moderation workflow được thay đổi.

## Không lưu Rating trong V1

Không thêm:

```text
rating_avg
rating_count
```

vào Shop source-of-truth.

Đây là derived metrics từ Review Module.

Tương lai có thể materialize:

```text
shop_metrics
```

hoặc search/read projection.

## Delete Policy

Shop đã hoạt động không physical delete.

Sử dụng lifecycle:

```text
draft
  ↓
active
  ↓
suspended

active
  ↓
closed
```

# 7. TABLE: `shop_memberships`

**Owner:** Seller Module

## Purpose

Mapping SellerAccount vào Shop và lưu shop-scoped authorization.

Đây là source of truth cho quyền Seller trong Shop.

## Columns

| Column                         | Type        | Null | Default     | Constraint |
| ------------------------------ | ----------- | ---: | ----------- | ---------- |
| `id`                           | UUID        |   NO | —           | PK         |
| `shop_id`                      | UUID        |   NO | —           | FK         |
| `seller_account_id`            | UUID        |   NO | —           | FK         |
| `created_by_seller_account_id` | UUID        |  YES | NULL        | FK         |
| `role`                         | VARCHAR(30) |   NO | —           | CHECK      |
| `status`                       | VARCHAR(20) |   NO | `'pending'` | CHECK      |
| `invited_at`                   | TIMESTAMPTZ |  YES | NULL        | CHECK      |
| `accepted_at`                  | TIMESTAMPTZ |  YES | NULL        | CHECK      |
| `revoked_at`                   | TIMESTAMPTZ |  YES | NULL        | CHECK      |
| `created_at`                   | TIMESTAMPTZ |   NO | `now()`     |            |
| `updated_at`                   | TIMESTAMPTZ |   NO | `now()`     | CHECK      |

## Foreign Keys

```sql
FOREIGN KEY (shop_id)
REFERENCES shops(id)
ON DELETE RESTRICT
```

```sql
FOREIGN KEY (seller_account_id)
REFERENCES seller_accounts(id)
ON DELETE RESTRICT
```

```sql
FOREIGN KEY (created_by_seller_account_id)
REFERENCES seller_accounts(id)
ON DELETE RESTRICT
```

`created_by_seller_account_id` nullable vì membership có thể xuất phát từ:

```text
initial shop creation
admin operation
migration
system workflow
```

## Unique

```sql
UNIQUE (shop_id, seller_account_id)
```

Một Seller không có nhiều membership records song song trong cùng Shop.

Nếu Seller bị revoke rồi được mời lại, V1 reactivate/update membership hiện tại thay vì tạo duplicate membership identity.

## Role

```sql
CHECK (
    role IN (
        'owner',
        'admin',
        'catalog_manager',
        'order_manager',
        'viewer'
    )
)
```

Đây là shop-scoped role.

## Status

```sql
CHECK (
    status IN (
        'pending',
        'active',
        'suspended',
        'revoked'
    )
)
```

Lifecycle:

```text
pending
   │
   ▼
active
   ├──► suspended
   └──► revoked
```

## Timestamp Constraints

```sql
CHECK (
    invited_at IS NULL
    OR invited_at >= created_at
)
```

```sql
CHECK (
    accepted_at IS NULL
    OR accepted_at >= COALESCE(invited_at, created_at)
)
```

```sql
CHECK (
    status <> 'pending'
    OR accepted_at IS NULL
)
```

```sql
CHECK (
    status NOT IN ('active', 'suspended', 'revoked')
    OR accepted_at IS NOT NULL
)
```

```sql
CHECK (
    (status = 'revoked' AND revoked_at IS NOT NULL)
    OR
    (status <> 'revoked' AND revoked_at IS NULL)
)
```

```sql
CHECK (
    revoked_at IS NULL
    OR revoked_at >= accepted_at
)
```

```sql
CHECK (updated_at >= created_at)
```

## One Active Owner

```sql
CREATE UNIQUE INDEX uq_shop_memberships_active_owner
ON shop_memberships(shop_id)
WHERE role = 'owner'
  AND status = 'active';
```

Invariant:

```text
mỗi Shop có tối đa một Active Owner
```

DB chưa thể đảm bảo đơn giản rằng Shop **luôn có ít nhất một** Active Owner.

Shop creation/ownership transfer phải thực hiện trong transaction.

## Indexes

```sql
CREATE INDEX idx_shop_memberships_seller_status
ON shop_memberships(seller_account_id, status);
```

```sql
CREATE INDEX idx_shop_memberships_shop_seller_active
ON shop_memberships(shop_id, seller_account_id)
WHERE status = 'active';
```

```sql
CREATE INDEX idx_shop_memberships_pending
ON shop_memberships(seller_account_id)
WHERE status = 'pending';
```

## Authorization

Request:

```text
PATCH /shops/{shopId}/products/{productId}
```

phải kiểm tra:

```text
SellerAccount.status = active
Shop.status = active
Membership.status = active
Membership.role allows catalog mutation
```

Sau đó resource lookup:

```sql
SELECT ...
FROM products
WHERE id = $1
  AND shop_id = $2;
```

Điều này chống Seller A thao tác Product của Seller B.

# 8. TABLE: `categories`

**Owner:** Catalog Module

## Purpose

Global product taxonomy.

Ví dụ:

```text
Electronics
└── Phones
    ├── Android
    └── iPhone
```

V1 sử dụng Adjacency List.

## Columns

| Column             | Type         | Null | Default    | Constraint    |
| ------------------ | ------------ | ---: | ---------- | ------------- |
| `id`               | UUID         |   NO | —          | PK            |
| `parent_id`        | UUID         |  YES | NULL       | FK, CHECK     |
| `name`             | VARCHAR(160) |   NO | —          | CHECK         |
| `slug`             | VARCHAR(160) |   NO | —          | scoped UNIQUE |
| `icon_object_key`  | VARCHAR(512) |  YES | NULL       |               |
| `image_object_key` | VARCHAR(512) |  YES | NULL       |               |
| `status`           | VARCHAR(20)  |   NO | `'active'` | CHECK         |
| `sort_order`       | INTEGER      |   NO | `0`        | CHECK         |
| `created_at`       | TIMESTAMPTZ  |   NO | `now()`    |               |
| `updated_at`       | TIMESTAMPTZ  |   NO | `now()`    | CHECK         |

## Foreign Key

```sql
FOREIGN KEY (parent_id)
REFERENCES categories(id)
ON DELETE RESTRICT
```

## CHECK Constraints

```sql
CHECK (
    parent_id IS NULL
    OR parent_id <> id
)
```

```sql
CHECK (
    char_length(btrim(name)) BETWEEN 1 AND 160
)
```

```sql
CHECK (
    slug = lower(btrim(slug))
    AND slug <> ''
)
```

```sql
CHECK (
    status IN ('active', 'inactive')
)
```

```sql
CHECK (sort_order >= 0)
```

```sql
CHECK (updated_at >= created_at)
```

## Slug Uniqueness

Root:

```sql
CREATE UNIQUE INDEX uq_categories_root_slug
ON categories(slug)
WHERE parent_id IS NULL;
```

Sibling:

```sql
CREATE UNIQUE INDEX uq_categories_parent_slug
ON categories(parent_id, slug)
WHERE parent_id IS NOT NULL;
```

Cho phép:

```text
Electronics
└── Accessories

Fashion
└── Accessories
```

## Indexes

```sql
CREATE INDEX idx_categories_parent
ON categories(parent_id);
```

Status index chỉ thêm nếu workload chứng minh cần.

## Không lưu `level`

Không thêm:

```text
level
```

vì đây là derived data từ hierarchy.

Move một subtree sẽ buộc update depth của toàn bộ descendants.

V1 tránh duplicated source of truth.

## Không lưu `is_leaf`

Không thêm:

```text
is_leaf
```

vì có thể derive:

```sql
NOT EXISTS (
    SELECT 1
    FROM categories child
    WHERE child.parent_id = categories.id
)
```

Nếu cần business rule "category có cho phép Product trực tiếp hay không", nên tạo semantic field riêng trong ticket tương lai.

## Cycle

DB chặn trực tiếp:

```text
A → A
```

nhưng chưa chặn:

```text
A → B → C → A
```

Service phải validate ancestors khi move Category.

Category tree modification nên chạy transactionally.

## Delete Policy

Không physical delete Category đang được tham chiếu.

Sử dụng:

```text
status = inactive
```

## Purpose

Nhóm variation chung của Product.

Ví dụ:

```text
Product: T-Shirt
Variant: Black
SKU: Black / Size M
```
