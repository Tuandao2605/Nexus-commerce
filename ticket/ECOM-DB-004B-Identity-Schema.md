# ECOM-DB-004B — Identity Schema

Status: DONE

## Source Design

- DATA-003A — Identity
- DATA-003G — Full ERD corrections

## Goal

Implement PostgreSQL schema for:

- users
- credentials
- sessions
- user_addresses

## Important Invariants

- One email/password Credential per User
- Login email is trimmed, lowercase and globally unique
- User status and soft-delete timestamp must remain consistent
- Session expiry must be after creation
- Session activity and revocation cannot be before creation
- One default Address per User
- Identity child records require an existing User
- A User with Identity child records cannot be physically deleted

## Implementation

Migrations:

- `000001_identity.up.sql`
- `000001_identity.down.sql`

Integration support:

- `internal/database/identity_migration_test.go`
- `docker/postgres/init/002-ensure-test-databases.sh`

Important DB constraints:

- `credentials.user_id` is both PK and FK
- UNIQUE canonical credential email
- partial UNIQUE default address per User
- CHECK constraints for lifecycle states and timestamp chronology
- `ON DELETE RESTRICT` for Identity child FKs
- UUID primary keys have no database-generated UUIDv4 default
- absolute timestamps use `TIMESTAMPTZ`

## Decisions

- UUIDv7 generated by Go
- absolute time stored as `TIMESTAMPTZ`
- lifecycle values use `VARCHAR` + `CHECK`, not PostgreSQL ENUM
- Identity foreign keys use `ON DELETE RESTRICT`
- Authentication email belongs to Credential, not User
- PostgreSQL access prioritizes pgx + sqlc; no GORM
- sqlc queries and repositories are deferred to their implementation tickets
