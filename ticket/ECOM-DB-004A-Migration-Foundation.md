# ECOM-DB-004A — Migration Foundation

Status: DONE

## Source Design

- NEXUS-COMMERCE V1 Canonical Roadmap
- Nexus Commerce Go Requirements

## Goal

Establish the PostgreSQL foundation for:

- Docker Compose PostgreSQL
- pgx/v5 + pgxpool
- strict database configuration
- application startup/shutdown lifecycle
- golang-migrate tooling
- isolated migration and integration testing

## Important Invariants

- `DATABASE_URL` is required
- Invalid database and pool configuration is rejected
- Application starts only after PostgreSQL `Ping` succeeds
- Database startup is bounded by a timeout
- HTTP requests finish draining before the pool is closed
- Database pool has one lifecycle owner and is not global
- Domain integration and migration probe use separate databases
- Migration probe must not reserve a version in the domain migration history

## Implementation

Infrastructure and configuration:

- `docker-compose.yml`
- `docker/postgres/init/001-create-test-database.sql`
- `docker/postgres/init/002-ensure-test-databases.sh`
- `.env.example`
- `Makefile`

Go database lifecycle:

- `internal/config/config.go`
- `internal/config/config_test.go`
- `internal/database/postgres.go`
- `internal/database/postgres_test.go`
- `cmd/api/main.go`

Migration probe:

- `testdata/migrations/000001_probe.up.sql`
- `testdata/migrations/000001_probe.down.sql`

Important implementation choices:

- `pgxpool.ParseConfig` + `pgxpool.NewWithConfig`
- Connectivity verified with `Ping`
- golang-migrate CLI pinned to `v4.18.3`
- Domain migrations and migration-engine fixtures have independent version tables
