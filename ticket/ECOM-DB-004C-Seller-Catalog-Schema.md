# ECOM-DB-004C — Seller + Catalog Schema

Status: DONE

## Source Design

- DATA-003B — Seller + Catalog
- DATA-003G — Full ERD corrections

## Goal

Implement PostgreSQL schema for:

- seller_accounts
- shops
- shop_memberships
- categories
- brands
- products
- product_variants
- skus

## Important Invariants

- One SellerAccount per User
- One active owner per Shop
- Product belongs to exactly one Shop
- Variant.shop_id must match Product.shop_id
- SKU.shop_id must match Variant.shop_id
- One Shop uses one currency
- SKU currency must match Shop currency
- SKU code unique inside one Shop
- Product → Variant → SKU is the mandatory sellable chain
- Inventory fields must not exist in SKU

## Implementation

Migrations:

- `000002_seller.up.sql` creates SellerAccount, Shop, membership constraints and indexes
- `000002_seller.down.sql` rolls back Seller tables in dependency-safe order
- `000003_catalog.up.sql` creates Category, Brand, Product, Variant and SKU constraints/indexes
- `000003_catalog.down.sql` rolls back Catalog tables in dependency-safe order

Integration tests:

- `migration_test_helpers_test.go` provides shared PostgreSQL transaction, UUIDv7 and SQLSTATE helpers
- `seller_catalog_migration_test.go` proves Seller/Catalog schema invariants on PostgreSQL
- `identity_migration_test.go` now uses the shared migration test helpers

Important DB constraints:

- `UNIQUE(user_id)` on SellerAccount
- `UNIQUE(shop_id, seller_account_id)` on Membership
- partial UNIQUE active owner per Shop
- `UNIQUE(id, currency_code)` on Shop
- `UNIQUE(id, shop_id)` on Product, Variant and SKU
- composite FK Variant → Product/Shop
- composite FK SKU → Variant/Shop
- composite FK SKU → Shop/Currency
- `UNIQUE(shop_id, sku_code)` on SKU
- `ON DELETE RESTRICT` on every Seller/Catalog FK

## Decisions

- UUIDv7 generated by Go
- price stored as BIGINT minor units
- no PostgreSQL ENUM
- no inventory fields in Catalog
- no Elasticsearch in V1
- database guarantees at most one active owner; Shop workflow transaction guarantees at least one
- database requires every Variant to reference Product and every SKU to reference Variant
- Product publish workflow must create a Default Variant and Default SKU when no visible options exist
- PostgreSQL access prioritizes pgx + sqlc; no GORM
- pgx is used for integration tests; sqlc queries/repositories remain scoped to ECOM-DB-005
